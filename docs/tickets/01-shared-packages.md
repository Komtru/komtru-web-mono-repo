### T-011 — `ui-kit` tokens, fonts and brand mark

- **Status:** Done (2026-10-05). Plan: `docs/superpowers/plans/2026-10-05-t-011-ui-kit-tokens.md`. The HTML declares the ticket's 52 properties, repeated identically across five `:root` blocks; `packages/ui-kit/scripts/extract-tokens.ts` generates `src/tokens.css`, `src/tokens.ts` and `packages/config/tailwind/preset.css` from them, and `packages/ui-kit/test/tokens.test.ts` re-parses the HTML to prove all three still agree.
- **Deferred:**
  - The radius utilities are `rounded-sm/md/lg/full`, not the ticket's `rounded-r-md`: `r` is Tailwind's own side modifier, so `rounded-r-md` sets the two right corners. Proved by a compiler test in `packages/config/test/tailwind-preset.test.ts`.
  - Tailwind v4 has no duration namespace, so the four `--dur-*` tokens stay plain custom properties, used as `var(--dur-standard)`.
  - Tailwind's default _colour_ palette is retired (`--color-*: initial`) so every colour utility names a reference token; its spacing, radius, font-size and shadow defaults remain, because the reference itself uses off-scale values (11px, 13.5px, 2.5px rings).
  - The shared lint rule is `komtru-design/no-raw-hex`, not `komtru/…`: `apps/backend-api` already defines a `komtru` ESLint plugin and ESLint rejects a duplicate plugin name. Unifying the two namespaces is left to T-017. The rule only sees JS/TS; app CSS (arriving in T-017) needs a stylelint or `@eslint/css` pass.
  - `packages/ui-kit` overrides the shared library tsconfig with `moduleResolution: bundler` and `jsx: react-jsx`, because `next` ships no `exports` map and NodeNext cannot resolve `next/font/google`. A test in `test/index.test.ts` keeps the `.js` import extension convention that NodeNext used to enforce.
  - `src/tokens.css` and `packages/config/tailwind/preset.css` are in `.prettierignore`: Prettier lowercases hex, rewrites `.4` to `0.4` and respaces `rgba(...)`, which would break literal parity with the HTML.
  - `<KomtruMark>` draws the emerald, round-capped variant the ticket specifies. The reference also contains capless marks, a `currentColor` one and a 40px `stroke-width:1.6` splash mark; T-016's diff should expect those as known deviations.
  - Nothing outside a Next build loads the actual webfaces — `tokens.css` names the families but ships no `@font-face` — so T-012's Storybook and T-016's harness need to inject the font stylesheet themselves or expect a typography delta.
- **Touches:** `packages/ui-kit/src/tokens.css`, `src/tokens.ts`, `src/brand/{KomtruMark,KomtruLogo}.tsx`, `src/fonts.ts`, `packages/config/tailwind/preset.css`, `scripts/extract-tokens.ts`
- **Depends on:** T-002
- **Acceptance criteria:**
  - `tokens.css` contains the HTML's 52 `:root` custom properties exactly (colours, semantic `-soft` and `-on-soft` pairs, `--font-display/body/mono`, `--sp-*`, `--r-*`, `--shadow-*`, `--dur-*`, `--ease-standard`), generated by `extract-tokens.ts` from `docs/design-reference/`.
  - A parity test re-parses the HTML and fails on any difference in name or value.
  - Tailwind v4 `@theme` maps tokens to utilities (`bg-trust-indigo`, `rounded-r-md`, `font-display`, spacing from `--sp-*`), so apps never hard-code a hex value. A lint rule rejects raw hex colours in app code.
  - Space Grotesk, Inter and IBM Plex Mono load through `next/font` with the HTML's fallbacks.
  - `<KomtruMark />` is the literal three-node SVG (emerald stroke, round caps); `<KomtruLogo product?>` renders mark plus "Komtru" or "Komtru Ops" in Space Grotesk 600, matching `.scr-logo` and `.ds-logo`.
  - No dark theme is introduced (the HTML defines none).

### T-012 — `ui-kit` core primitives and Storybook

- **Status:** Done (2026-10-05). Plan: `docs/superpowers/plans/2026-10-05-t-012-ui-primitives.md`. Nineteen primitives live in `packages/ui-kit/src/primitives/**`, each emitting only the token utilities `@komtru/config`'s Tailwind preset publishes. `packages/ui-kit/test/primitives-parity.test.tsx` renders every primitive, compiles its classes through the real preset and diffs the declarations against the rule the reference HTML declares for it — 132 parity checks — so a property a primitive does not reproduce has to be named in `DEVIATIONS` with a reason, a property it applies that the reference does not has to be named in `ADDITIONS`, and an entry in either that no longer applies fails too. `src/primitives/DEVIATIONS.md` is that list in prose, with the screen and line number T-016 should shoot each primitive against. Storybook 10.6.1 (`@storybook/react-vite`, Vite 8) has one story file per primitive with a story per documented state. 305 tests in `@komtru/ui-kit`.
- **Reviewed:** two independent whole-branch reviews. The second found that the parity harness modelled the cascade wrongly — it merged same-property utilities in the order they appear in the `class` attribute, where a browser uses stylesheet order — and that this was concealing live rendering bugs: `OtpInput`'s filled and invalid cells both lost their background to the base, so E3b's entire wrong-code treatment did not render. The harness now resolves by emission order, a new guard fails any element that claims a decisive property twice, and the invalid state is compared against E3b's own inline `style` attribute since the reference declares it in no rule. Earlier findings, all landed: (1) The parity harness only diffed one way, so it was blind to anything a primitive _adds_ — an invisible `hidden opacity-0` button passed. It now diffs both directions against an `ADDITIONS` table with the same reason-and-staleness rules as `DEVIATIONS`, and the reviewer's counter-example fails. (2) `Toggle` emitted both `bg-trust-emerald` and `bg-stone-gray` for a locked-and-on switch, leaving the cascade to pick — and Tailwind's order picked emerald, the opposite of `.m-switch.locked`. That is the only locked switch the reference draws. (3) `DEVIATIONS.md` claimed `Banner (info)` deviated in nothing while the component applied one body/icon treatment to all four tones; the info note is 11.5px at 1.5 behind a 15px icon, the alert banners 11px at 80% behind a 16px icon. Ten further suggestions were taken: a focus trap in `Sheet`, a throw when a class compiles to no rule, a guard against a misspelled `DEVIATIONS` property, the `.proof-thumb .play-badge`, the reference's own gate copy, `.ko-step-line`'s margins, and honest wording for `MediaGate`. Parity grew from 53 checks to 66.
- **Deferred:**
  - **No primitive has had a screenshot taken.** T-016's harness did not exist in this worktree. It does now — `pnpm visual-check --screen <id> --url <url>` closes the gap, and `src/primitives/DEVIATIONS.md` names the screen and line to shoot each of the nineteen against.
  - The reference declares no toast rule and says so out loud ("A real moment, not just a toast", line 3978). `<Toast>` borrows `.offline-banner`'s geometry, is scoped to small confirmations, and has no reference instance to shoot.
  - `.scope-note` is the design document's own page chrome, not a product component — its five copies disagree on `max-width` (700/760/780px). The product's info note is `.proof-compare-note`, which is `<Banner tone="info">`. The risk tone is an extrapolation: the reference has no banner in it.
  - **T-017 owes the app three things `ui-kit` cannot ship**, because it has no stylesheet beyond `tokens.css`. `.storybook/preview.css` carries all three so the stories are honest. (a) `@keyframes shimmer` and `@keyframes nodePulse`, or `<Skeleton>` and `<NodeLoader>` sit still. (b) The global `:focus-visible` rule — primitives carry the ring as a utility, but any focusable element a _screen_ adds gets it only from the global rule, so without it those elements have a ring in Storybook and none in the app. (c) The reference's element defaults (`body`, `h1–h4`, `p`, `img`/`svg`).
  - `className` on a primitive **appends, it does not override**: two utilities for one property are resolved by stylesheet order, so `<Card className="rounded-[10px]">` keeps `rounded-md` as often as not. Documented on `cx` with a test. Screens that need a different value need a prop, not a class.
  - `.ko-stepper` is restated three times in the reference as three different designs (`komtru-refinement-v2` numbered inline rail, `komtru-nav-v2` centred-dot rail, `.p0-stepper`). `<Stepper>` reproduces the first; the parity row names the `<style>` id so the choice is explicit.
  - The reference's global `:focus-visible` also sets `border-radius:4px`. It is not reproduced: that rule is declared before every component rule, so in the reference any element with its own radius keeps it, and baking 4px into a utility would invert the cascade.
  - `<Toggle>`'s knob is a real `<span>`, not `.m-switch::after`, and `<FileDropzone>`'s upload target is a `<label>` wrapping a visually hidden file input rather than the reference's non-functional `<div>`: a kit that ships no stylesheet cannot reach a pseudo-element, and a dropzone has to actually take a file.
  - `<Sheet>`'s scrim is `fixed`, not `absolute`, and drops its `border-radius`: the reference pins it inside the 340px phone frame it is drawn in, and a real screen has no frame.
  - Added beyond the HTML, consistently and deliberately: `motion-reduce:animate-none` on every animation, `aria-disabled` plus `opacity-55` on a disabled button (the reference never draws one), and an `aria-invalid` + risk-border error treatment on `TextField`/`Select` (the reference styles only the message).
  - **`TextField` and `Select` are client components**, which the plan's RSC list did not anticipate: both call `useId` to tie label to control. That makes every form field in the product a client component. The alternative is a required `id` prop on every field, which pushes the bookkeeping onto 200-odd screens; `useId` is the better trade, but it is a trade. `Toast` went the other way — it only forwards `onDismiss`, so it needs no boundary and now has none.
  - `FileDropzone` is finished rather than deferred: it takes a drop as well as a click, `onRemove` puts a wrong photo back, and `requiredCount` is **required** with no default — a gate that defaults open is a gate nobody set, and "a seller cannot accept sight-unseen" is too important to inherit by omission. The reference draws no drag state, so the dragging treatment borrows the focused-input look it does draw.
  - Parity rows address elements by position in the rendered markup (`node: 8`) and `classAttributes` skips class-less elements, so adding a class to a wrapper shifts every index below it. It fails loudly rather than silently, so this is a maintenance cost rather than a correctness risk; addressing by a `data-parity` attribute is the obvious later improvement.
  - `build-storybook` is a package script, not a turbo task: it is a 1s Vite build that nothing else depends on, and wiring it into `turbo run build` would put it on every ticket's critical path. Run `pnpm --filter @komtru/ui-kit build-storybook` to check it.
  - `packages/ui-kit/tsconfig.json` now includes `.storybook/*.ts` explicitly — TypeScript's `include` globs skip dot-directories, and typescript-eslint's project service refuses to parse a file the program does not contain.
- **Touches:** `packages/ui-kit/src/primitives/**`, `packages/ui-kit/.storybook/**`
- **Depends on:** T-011
- **Acceptance criteria:**
  - Components matching the HTML's classes: Button (`btn-primary`, `btn-secondary`, sticky footer), Chip (`protected`, `awaiting`, `risk`, `resolved`, `verified`), Avatar, Card, TradeRow (`trade-row` with amount, parties, 5-step progress), Stepper, OtpInput (`otp-cell`), TextField, Select, Toggle, Sheet/Modal, Toast, Skeleton plus node-pulse loader, EmptyState (explain → benefit → action), Banner/scope-note, FileDropzone with mandatory-media gate.
  - Each has a Storybook story and a Vitest + Testing Library test covering states and keyboard focus (`:focus-visible` indigo ring from the HTML).
  - Visual check (T-016) for each primitive against an HTML instance; deviations listed.

### T-016 — Visual-check harness

- **Status:** Done (2026-10-05). Plan: `docs/superpowers/plans/2026-10-05-t-016-visual-check.md`. `tools/visual-check` is a workspace package (`@komtru/visual-check`) run from source by the root `pnpm visual-check` script; `docs/ui-review/README.md` is the account every UI ticket needs.
- **Deferred:**
  - The three brand webfonts ship as exact-pinned Fontsource dependencies (`@fontsource/space-grotesk`, `@fontsource-variable/inter`, `@fontsource/ibm-plex-mono`, all 5.3.0), `latin` subset, in the same weights `packages/ui-kit/src/fonts.ts` asks next/font for, and are inlined into **both** pages. Masking text was rejected because in a design-system build most deviations are text; linking Google Fonts at screenshot time was rejected because it makes the diff irreproducible offline. T-011's note that the harness would need to solve this is now closed.
  - Two limits on the font parity, recorded rather than claimed away: next/font renders the built app under a generated family name, so the injected faces apply only to the reference page and the two sides run **independently produced builds** of the same typefaces. A sub-pixel metric skew between a Fontsource release and the Google Fonts API's output is possible and nothing measures it yet — the airtight fix is for `@komtru/ui-kit` to own the font files both sides load, which needs a real screen to measure against. Separately, `₦` (U+20A6) is outside the Google `latin` subset both sides use, so it comes from a system fallback by slightly different routes on each side; treat naira glyphs as a known deviation until a real screen says otherwise.
  - The PNGs are not committed (`.gitignore` carries `docs/ui-review/**/*.png`); the `.md` deviation lists are. Re-running a check refreshes the metadata and keeps whatever was written under `## Deviations`.
  - The carved reference page renders at the gallery's own 1280px with the frame pinned to its declared width, not at the frame's width. The reference carries `@media(max-width:900px)` rules from the design system it was assembled from, and at a 560px viewport those fire and redraw a tablet screen as something the reference never shows. The built page still gets a viewport of exactly the compared size.
  - The shot is clipped to the frame's content, excluding the mock browser bezel and its border, radius, shadow and padding — which is also what makes it exactly 340/560/1040 wide rather than two pixels short. P1 is the one screen drawn in the design system's phone bezel (`.device.phone`, 230px) rather than a browser frame; its `.device-screen` keeps its own 14px radius, so its corners are a known small deviation.
  - Widths come from six reference rules, re-parsed on every run with T-011's `parseCssDeclarations`: 340 (`.mweb-frame`), 230 (`.device.phone`), 560 (tablet) and 1040 (desktop), the last two exactly as the reference's own `#p3-proportion-fix-v8` comment states them.
  - `packages/ui-kit` gained one export, `"./extract-tokens": "./scripts/extract-tokens.ts"`, so the harness reuses T-011's parsers instead of growing a second set. It points at source because `tsconfig.build.json` only emits `src`, which is the same thing `"./tokens.css"` already does.
  - `pnpm-workspace.yaml` gained `tools/*` so turbo lints, typechecks and tests the harness and the `repo` workflow's unfiltered job covers it. Only directories with a `package.json` match, so `tools/tickets` (Python) is unaffected.
  - Relative imports inside `tools/visual-check` carry `.ts`, not the repo's usual `.js`: the package is never compiled, it runs under `node --experimental-strip-types`, and Node resolves the file on disk rather than rewriting the extension.
  - The reference HTML does not close every element it opens — TO-PA9's frame runs straight into the next section — so the carve recovers the way a browser does and closes what is left open. A test carves all 210 screens and asserts each document balances.
  - `.github/workflows/repo.yml` gained a step that runs `pnpm browsers:install`, `pnpm test:browser` and the harness's own browser-gated suite. Without it `KOMTRU_BROWSER_TESTS=1` was set nowhere in CI, so the twelve tests that prove the harness still takes a correct screenshot — including "a screen against itself scores zero" — never ran. This also closes the same pre-existing gap for `scripts/test/playwright-browser.test.ts`.
  - The deviation stub carries no capture timestamp: it is a committed file, and a timestamp above the merge boundary would diff on every run. `git log` already says when a review was taken.
  - Anti-aliased pixels are excluded from the score _and_ from the heat map (`aaColor`), because pixelmatch's default paints them yellow and on a text-heavy screen that is more highlighted area than the red it counts.
  - No threshold gate: the CLI reports the ratio and exits 0 unless it errors. What counts as an acceptable deviation is a judgement each screen ticket writes down, not a number the harness can hold.
  - Screenshots are deterministic on one machine, not across machines: Chromium rasterises text differently per platform. Compare a run against the reference, never against someone else's PNG.
- **Touches:** `tools/visual-check/**`, `docs/ui-review/README.md`
- **Depends on:** T-011
- **Acceptance criteria:**
  - `pnpm visual-check --screen U4 --url http://localhost:3004/handover/KMT-88213` renders the HTML reference screen (located via `SCREEN_INDEX.md`) and the built screen at the same viewport (340px mobile frame width, or the desktop/tablet width the reference uses) and writes `docs/ui-review/<ticket>/<screen>.png` side by side, plus a pixel-diff heat map.
  - Output includes a markdown stub where the deviation list is written.
  - Works for mobile, desktop and tablet reference frames.
