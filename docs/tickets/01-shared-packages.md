### T-010 — `shared-types` foundations

- **Status:** Done (2026-10-05). Plan: `docs/superpowers/plans/2026-10-05-t-010-shared-types.md`.
- **Touches:** `packages/shared-types/src/{money,pagination,errors,ids,enums,index}.ts`
- **Depends on:** T-002
- **Acceptance criteria:**
  - zod is the single schema language. Every exported DTO has a zod schema and an inferred type.
  - Money: kobo values travel as strings in JSON and are parsed to `bigint`; helpers for formatting `₦452,000.00` with the IBM Plex Mono convention used in the HTML; property tests prove no float ever appears.
  - Pagination: `CursorPageRequest`, `PageRequest`, `Paginated<T>` contracts shared by backend and clients.
  - Errors: RFC 9457 problem-details type with a stable `code` union (for example `INVALID_TRANSITION`, `NO_LOGISTICS_ACCESS`, `LAST_ADMIN`).
  - Public id formats (`KMT-U-…`, trade codes `KMT-88213`, hub codes `H-JIB-004`) have validators.
  - Enums shared with the backend live here, never duplicated in apps.

### T-011 — `ui-kit` tokens, fonts and brand mark

- **Status:** Done (2026-10-05). Plan: `docs/superpowers/plans/2026-10-05-t-011-ui-kit-tokens.md`. The HTML declares the ticket's 52 properties, repeated identically across five `:root` blocks; `packages/ui-kit/scripts/extract-tokens.ts` generates `src/tokens.css`, `src/tokens.ts` and `packages/config/tailwind/preset.css` from them, and `packages/ui-kit/test/tokens.test.ts` re-parses the HTML to prove all three still agree.
- **Deferred:**
  - The radius utilities are `rounded-sm/md/lg/full`, not the ticket's `rounded-r-md`: `r` is Tailwind's own side modifier, so `rounded-r-md` sets the two right corners. Proved by a compiler test in `packages/config/test/tailwind-preset.test.ts`.
  - Tailwind v4 has no duration namespace, so the four `--dur-*` tokens stay plain custom properties, used as `var(--dur-standard)`.
  - Tailwind's default _colour_ palette is retired (`--color-*: initial`) so every colour utility names a reference token; its spacing, radius, font-size and shadow defaults remain, because the reference itself uses off-scale values (11px, 13.5px, 2.5px rings).
  - The shared lint rule is `komtru-design/no-raw-hex`, not `komtru/…`: `apps/backend-api` already defines a `komtru` ESLint plugin and ESLint rejects a duplicate plugin name. Unifying the two namespaces is left to T-017. The rule only sees JS/TS; app CSS (arriving in T-017) needs a stylelint or `@eslint/css` pass.
  - `packages/ui-kit` overrides the shared library tsconfig with `moduleResolution: bundler` and `jsx: react-jsx`, because `next` ships no `exports` map and NodeNext cannot resolve `next/font/google`. A test in `test/index.test.ts` keeps the `.js` import extension convention that NodeNext used to enforce.
  - `src/tokens.css` and `packages/config/tailwind/preset.css` are in `.prettierignore`: Prettier lowercases hex, rewrites `.4` to `0.4` and respaces `rgba(...)`, which would break literal parity with the HTML.
  - `<KomtruMark>` draws the emerald, round-capped variant the ticket specifies. The reference also contains capless marks, a `currentColor` one and a 40px `stroke-width:1.6` splash mark; T-016's diff should expect those as known deviations.
  - Nothing outside a Next build loads the actual webfaces — `tokens.css` names the families but ships no `@font-face` — so T-012's Storybook and T-016's harness need to inject the font stylesheet themselves or expect a typography delta.
- **Touches:** `packages/ui-kit/src/tokens.css`, `src/tokens.ts`, `src/brand/{KomtruMark,KomtruLogo}.tsx`, `src/fonts.ts`, `packages/config/tailwind/preset.css`, `scripts/extract-tokens.ts`
- **Depends on:** T-002
- **Acceptance criteria:**
  - `tokens.css` contains the HTML's 52 `:root` custom properties exactly (colours, semantic `-soft` and `-on-soft` pairs, `--font-display/body/mono`, `--sp-*`, `--r-*`, `--shadow-*`, `--dur-*`, `--ease-standard`), generated by `extract-tokens.ts` from `docs/design-reference/`.
  - A parity test re-parses the HTML and fails on any difference in name or value.
  - Tailwind v4 `@theme` maps tokens to utilities (`bg-trust-indigo`, `rounded-r-md`, `font-display`, spacing from `--sp-*`), so apps never hard-code a hex value. A lint rule rejects raw hex colours in app code.
  - Space Grotesk, Inter and IBM Plex Mono load through `next/font` with the HTML's fallbacks.
  - `<KomtruMark />` is the literal three-node SVG (emerald stroke, round caps); `<KomtruLogo product?>` renders mark plus "Komtru" or "Komtru Ops" in Space Grotesk 600, matching `.scr-logo` and `.ds-logo`.
  - No dark theme is introduced (the HTML defines none).

### T-015 — `api-client`

- **Touches:** `packages/api-client/src/**`
- **Depends on:** T-010
- **Acceptance criteria:**
  - Typed client generated from shared zod contracts; errors surface as typed problem details.
  - Access token kept in memory; on 401 a single-flight refresh via the app's auth route handler, then one retry.
  - Every mutating call that the backend marks retryable sends an `Idempotency-Key` (UUID v7) that is stable across retries of the same user action.
  - Optional durable retry queue (IndexedDB) for flaky connectivity, replaying with the original idempotency key; used by `park-agent-app`.
  - TanStack Query helpers for cursor pagination and optimistic updates; a Socket.IO provider per the frontend socket guide, with resync-on-reconnect.
  - Unit tests for refresh races, retry-with-same-key, and queue replay ordering.

### T-017 — Next.js app foundation

- **Touches:** `packages/ui-kit/src/next/**` or `packages/app-kit/**` (decided in-ticket, recorded), per-app template files
- **Depends on:** T-013, T-015
- **Acceptance criteria:**
  - Shared pieces every app composes: auth route handlers (`/api/auth/*`) that set the refresh token as an `httpOnly`, `Secure`, `SameSite=Lax` cookie scoped to the app's host; middleware that redirects unauthenticated users and checks the session scope the app requires; Sentry init; error boundary and not-found pages in the design language; Query and realtime providers.
  - A consumer token is rejected by the ops, logistics and park apps' middleware (test per scope).
  - `komtruEslint({ react: true })` gains the Next.js 15 and React rules (`eslint-config-next`, `react-hooks`), so every Next app lints with them; apps extend `@komtru/config/tsconfig/next.json` (created in T-002).
