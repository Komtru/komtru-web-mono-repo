### T-014 — `ui-kit` TrustOps patterns

- **Status:** Done (2026-10-06). Plan: `docs/superpowers/plans/2026-10-06-t-014-trustops.md`. Eleven patterns live in `packages/ui-kit/src/trustops/**` — `CaseLayout`, `DecisionPanel`, `AdvisoryBox`, `PolicyCite`, `EvidenceMatrix`, `Timeline`, `TrustTrail`, `KpiCard`, `DataTable`, `FilterBar`, `PeriodFilter` — each with a Storybook story per documented state and a Vitest + Testing Library test ending in an `axe-core` 4.14.0 pass. 551 tests in `@komtru/ui-kit`, 246 of them this ticket's.
- **The separation is structural, not a convention.** The ticket asks that the advisory be visually _and_ semantically separate from the actions. The reference draws three sibling `div`s, which to a screen reader is one undifferentiated run of text ending in three buttons, with "AI-suggested — not a decision" as a 10px line a user moving by control or by landmark never hears. Four things carry the separation instead. (1) `AdvisoryBox` is a `<section aria-label="AI-suggested — not a decision">` — a named `region` landmark a reader can jump to and, more to the point, jump out of. `region` rather than `complementary`, because an advisory is never top level and a nested complementary landmark is what axe's `landmark-complementary-is-top-level` exists to flag. (2) **Its children are typed `string | readonly string[]`, not `ReactNode`.** A string cannot contain a button, so "never inside the button group" is a compile error rather than a review habit; a runtime guard covers the JavaScript caller `tsc` never sees. (3) The actions sit in a named `role="group"` that is `aria-describedby` the divider and the citation, so arriving at the first action announces "Require verification before forwarding, button, a human decides, always. Applied per New-Buyer Proposal Policy §2.1" — the two lines the reference leaves as grey decoration become part of the control. (4) `policy` is required and `section` is a separate required field, so a panel cannot cite a policy without citing the clause inside it.
- **Reviewed:** one whole-branch review by a fresh reviewer, which found five real defects, one of them in the ticket's own acceptance criterion. **The reviewer broke the guarantee with two lines and the whole suite stayed green:** an `aria-owns` on the action group pointing at the advisory reparents it in the accessibility tree without moving it in the DOM, so every `contains()` assertion kept passing while a screen reader read the advice as part of the controls. Every separation test was a DOM-shape test. There are now two accessibility-tree tests — one that no element on the panel carries `aria-owns` at all, one that walks `aria-owns`/`aria-labelledby`/`aria-describedby`/`aria-controls` from the group and asserts none of them resolves to the advisory or anything inside it — and the reviewer's exact edit now fails both. The other four: (1) `Children.count` counts `false` and `null` as children, so the idiomatic `actions={canApprove && <Button/>}` sailed past the no-actions guard and rendered an empty group under an AI suggestion — exactly what the guard's error message says it prevents; `Children.toArray` does not, and five cases are now tabled. (2) The `aria-describedby` ids were derived from the policy citation to keep the panel a server component, so two panels citing the same clause — the ordinary queue case — emitted duplicate ids and the second described itself with the first one's divider and cite. axe reported that as `incomplete`, not as a violation, and the helper was only reading `violations`; both are fixed, and the panel now uses `useId`. (3) A blank `aria-label` leaves a `<section>` with no accessible name, which is not a landmark at all, so `advisoryLabel=""` deleted the semantic half of the separation while leaving the dashed border that makes it look intact — and the package teaches the empty-string-drops-it convention one file away on `TrustTrail`'s caption.
