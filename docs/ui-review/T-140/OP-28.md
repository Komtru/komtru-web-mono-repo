# OP-28 — Welcome, set up your account (T-140)

- **Reference:** `docs/design-reference/Komtru — UI Living Master v2.html` line 9285 (`ops.komtru.com/welcome`)
- **Built:** `/welcome#token=…` in `apps/operations-app`
- **Method:** compared by reading the reference markup and the built page in the browser pane. The pixel-diff harness was not run: the active-step state OP-28 draws only exists after a real invitation is accepted against a live backend, which this scaffold has no fixture for.

## Deviations

- **Page chrome.** The reference draws the six-step timeline in the console's 250px sidebar. The built page is a standalone page (centred column, Ops lockup above), with the timeline as the left column of a two-column grid. Reason: the invitee has no staff session, so there is no console shell to put it in, and the console's rail would list sections they cannot open.
- **Which step is active.** The reference shows step 1 done and step 2 active. The built page starts on step 1 (accept the invitation, which has no reference screen) and reaches the reference's state after the code is accepted. Step 2 then matches the reference's layout: "Two-step sign-in" panel left, "Why we ask" panel right, the same copy.
- **No QR code.** The reference draws a QR placeholder. The built page shows the setup key and an `otpauth://` link instead of adding a QR dependency to a scaffold. Intended; a QR renderer is a one-line follow-up when someone wants it.
- **The device row** ("Your device: MacBook · Lagos · will be remembered") is left out: there is no device endpoint.
- **Steps 3 to 6** are drawn as in the reference (dimmed pending nodes) and cannot be acted on: they belong to tickets that have not been built.
- **After setup** the page shows a success banner and a "Go to sign-in" link, which the reference does not draw. Recovery codes are shown once between the two.
