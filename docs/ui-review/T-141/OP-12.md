# OP-12 — Trade 360 (T-141)

- **Reference:** `docs/design-reference/Komtru — UI Living Master v2.html` line 9109
- **Built:** `/trades/[reference]` in `apps/operations-app`
- **Method:** compared by reading the reference markup (extracted with the base64 images stripped) against the built component and its test output. The pixel-diff harness was not run: every one of these screens sits behind a staff session and `GET /admin/me`, which does not exist yet, and the cases API has no fixture server, so the built page cannot be opened with data. Same limit T-140 recorded for OP-28. A screenshot pass is the first thing to do once `GET /admin/me` lands.

## Deviations

- **Only the case half of Trade 360 is drawn.** The reference shows a header (item, price, parties), a stage rail (Agreement, Protected, Shipped, Inspection, Release), people and money panels, and the Trust Trail. There is no staff Trade read, so the page shows the cases opened on the trade (found by `subjectType=TRADE`, `subjectId=<reference>`) and each case's Trust Trail.
- **Section.** The page sits under Trades, so it needs `trade.view` or `trade.view_all` to open and `cases.view` to read its data; a role with only the first sees the list's error state.
- **Trust Trail** uses the shared `TrustTrail` component with the case trail's own events, not the trade's agreement, funds and delivery events.
