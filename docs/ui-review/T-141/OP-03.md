# OP-03 — Team queue (T-141)

- **Reference:** `docs/design-reference/Komtru — UI Living Master v2.html` line 9028
- **Built:** `/queue/team` in `apps/operations-app`
- **Method:** compared by reading the reference markup (extracted with the base64 images stripped) against the built component and its test output. The pixel-diff harness was not run: every one of these screens sits behind a staff session and `GET /admin/me`, which does not exist yet, and the cases API has no fixture server, so the built page cannot be opened with data. Same limit T-140 recorded for OP-28. A screenshot pass is the first thing to do once `GET /admin/me` lands.

## Deviations

- **Who has capacity** panel (Amina, Tunde, You, Ngozi with open counts) is not drawn: there is no staff roster, shift or open-count read, and the console will not invent colleagues. Assigning to someone else is Reassign on the case page.
- **Take it** is a secondary button per row, shown only with `cases.manage`; it calls `POST /cases/:id/take` and the row leaves the list on refetch. A failed take (someone was faster) shows a banner and refreshes.
- **Columns.** Case, Area, What, Priority, Clock ("Waiting" in the reference is the age; the platform returns the clock remaining, not the age).
- The "Items needing Tier 2 go to Amina first" note is routing policy the platform does not hold, so it is not drawn.
