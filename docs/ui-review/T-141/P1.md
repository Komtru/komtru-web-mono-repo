# P1 — Proposal Queue — Mobile Check-in (T-141)

- **Reference:** `docs/design-reference/Komtru — UI Living Master v2.html` line 3814
- **Built:** `/queue/check-in` in `apps/operations-app`
- **Method:** compared by reading the reference markup (extracted with the base64 images stripped) against the built component and its test output. The pixel-diff harness was not run: every one of these screens sits behind a staff session and `GET /admin/me`, which does not exist yet, and the cases API has no fixture server, so the built page cannot be opened with data. Same limit T-140 recorded for OP-28. A screenshot pass is the first thing to do once `GET /admin/me` lands.

## Deviations

- **Phone frame.** The reference draws a device frame inside the master; the built page is a 420px column inside the console frame, so on a phone the rail collapses and the column fills the width.
- **Amounts.** The reference cards lead with the trade amount. A case carries no amount, so cards lead with the trade reference and show priority, state and the reason.
- **Flagged count** is the open `TRADE_PROPOSAL` cases among the first page loaded (a "+" is added when more pages exist). "Cleared today" is decided or closed proposals since local midnight, newest first, with how long ago.
- Cards link to the case page; the reference has no navigation target (it says working a proposal stays on the desktop console).
