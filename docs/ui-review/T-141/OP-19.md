# OP-19 — Cases (T-141)

- **Reference:** `docs/design-reference/Komtru — UI Living Master v2.html` line 9197
- **Built:** `/queue/cases` in `apps/operations-app`
- **Method:** compared by reading the reference markup (extracted with the base64 images stripped) against the built component and its test output. The pixel-diff harness was not run: every one of these screens sits behind a staff session and `GET /admin/me`, which does not exist yet, and the cases API has no fixture server, so the built page cannot be opened with data. Same limit T-140 recorded for OP-28. A screenshot pass is the first thing to do once `GET /admin/me` lands.

## Deviations

- **Summary tiles** (open 17, disputes 10, appeals 3, risk 4) are not drawn: the platform returns no per-type totals, and counting a partial page would show wrong numbers.
- **Chips.** The reference has All / Disputes / Appeals / Risk. The built chips are one per case type (Disputes, Risk, Proposals, Money, Custody, Identity, Business checks, Merchants, Park hubs) and filter server-side; there is no separate Appeals type in the cases index. A search box for the case number is added (the reference has none).
- **Columns.** Case, Type, What, State, Owner, Clock. The reference's Money column has no field on a case and is dropped.
- The "Returns & settlements" sub-heading is not drawn.
