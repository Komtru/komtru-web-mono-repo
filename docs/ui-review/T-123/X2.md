**Shell chrome and the stand-in.** The built screen sits in `AppShell` (shot with `--content main`) and its actions are in the page flow above the real tab bar, where the reference pins them in a sticky footer; the tab bar and the moved buttons light the foot of every heat map. The shot ran against the real production build and a canned stand-in for the platform (trade ids mapped to states, one proxy adding the sealed session cookie), so the data is illustrative: trade codes, names, amounts and dates differ from the drawing for that reason only. The shell is drawn for the anonymous viewer (Buy mode) because the viewer seam (`resolveViewer`) is not filled yet.

**Real differences (intended, and why)**

- **No logistics-method picker, no Park Hub Transit, no handover PIN.** Park (F-062) and courier companies (F-066) are dropped for MVP. The platform is still asked for the ship options; only "Arrange my own shipping" is acted on, and no Park option or reason is drawn. The screen is the self-arranged form on its own.
- **A "Ship by" countdown strip** from the delivery deadline, and a note that the seller arranges delivery themselves; the reference has neither.
- **Receipt photo** is a single compact picker showing the chosen file name, not a thumbnail slot.
- **Item card** as in X1. Field order and labels follow the platform's four required fields (waybill number, receipt photo, driver or rider phone, vehicle registration plate).
- **Mark as shipped** stays disabled until the four pieces of evidence are given.
