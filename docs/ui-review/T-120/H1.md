## Deviations

<!-- One line per deviation the heat map shows: what differs, where, and whether it is intended.
     Everything below this comment survives the next run; everything above it is regenerated. -->

**Scenario:** `dispute-decided`, buyer, `/trade/<id>/dispute/status`, refund in full, inside the appeal window.

- **Shell offset (standing).** The built screen sits under the app shell's Komtru bar (about 28px) and above the tab bar with its raised plus action; the reference frame draws neither, and its action is pinned (`.btn-sticky`) where the built one is in the page flow. Every line below the title therefore sits lower than in the reference, which is most of the heat map on every screen here. Not a defect of this screen.
- **Header block.** The reference opens with a bare "Resolved" chip; the built screen opens with the trade row (₦102,900.00, Resolved chip, trade code). Intended: it states what the outcome is about before the banner.
- **Banner.** "Refund issued in full — ₦102,900 has been returned..." is the same shape; the amount is the fixture's and the seller's name is the fixture seller (Tunde Bello).
- **Decision card.** Same structure. Text is the fixture's rationale.
- **Timeline.** Reference: "You filed this dispute / TechEdge NG responded / TrustOps reviewed & decided", each timed. Built: "You reported this issue / Tunde Bello was notified / The response window closed / Evidence / TrustOps decision". **Fixed this run:** the third step read "Awaiting the other side's response — Done" on a decided case, which is false in the present tense. It now reads "The response window closed". The built rail has five steps, not three, and no times; the platform does not say whether the seller responded, so "responded" is not claimed.
- **Actions.** The reference shows "File an appeal" and "Back to Trades"; the built shows the same two below the fold (scroll), in the page flow rather than pinned.
