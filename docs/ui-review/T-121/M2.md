## Entry points, by state

Every state the flow can be entered from has a way in. The entry is on this screen, and the row that leads here is on the account's Verification list.

| State             | Way into the flow                                           | Note                                                                         |
| ----------------- | ----------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Not started       | "Start merchant verification" → SO1                         |                                                                              |
| Draft             | "Continue your application" → first unfinished step         |                                                                              |
| In review         | No edit. "Contact support" only                             | The backend refuses edits while a person is reviewing (409). See the report. |
| Changes requested | Each named change links to the step that holds it ("Fix …") |                                                                              |
| Rejected (BVR1)   | "Resubmit CAC details" → SO3                                | Starts a new draft, since REJECTED is terminal                               |
| Approved          | "See your merchant status" → SO5                            | SO5 then goes to `/shop`                                                     |

## Deviations

- **Reference heading "Business Verification" becomes "Merchant verification".** Owner correction (2026-11-19): this is merchant status, gained by verifying CAC and the rest.
- **Reached from the account, not the Shop tab.** The screen sits under Account › Verification, with the account rail and Verification current. The reference draws it under the seller's tab.
- **Entry row on the Verifications list.** Account › Verification gains a "Merchant" group with a "Merchant verification" row. The reference has no such entry. The owner asked for the entry in the verifications tab; no row was added to the Account list or to the Shop tab.
- **Reference wording overridden: "Full business verification unlocks the Verified Merchant badge".** Kept in substance, and extended with the owner's model: merchant verification also lifts the limit on what an unverified default seller can transact. No figure is given, because the cap is not built.
- **Rows use ui-kit `TermList`/`TermRow`** rather than `.verify-row`. The status chip sits at the right, with the detail line under it (CAC number, bank and last four digits, address).
- **Storefront row follows the application.** Verified when approved, Verifying while in review, Changes requested only when staff named one of its fields, otherwise Not yet.
- **Owner identity row** is read from the ID and selfie checks, not drawn from the reference's "Checked 2024".
- **Not-started copy changed.** The reference draws no such state. The copy says the amount a default seller can transact is limited until the business is verified, and does not say an account cannot sell.
- **States not drawn in the reference, added:** not started, draft, in review, changes requested, approved. Rejected is BVR1.
- **Info banner** rewritten as above; the reference's line is the source.
