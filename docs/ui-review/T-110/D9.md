Shot for **T-013** (`ui-kit` layout shells) against Storybook story `Shells/DesktopShell` →
`Account`. The shell — 180px sidebar, `.ds-logo`, `.dweb-item` rail, 24px content — is this
ticket's; the Personal Info form is stand-in content. T-110 owns the screen.

**Shell chrome (T-013)**

- Nothing. The sidebar width, the hairline, the indigo active pill and the content padding land on
  the reference.
- The page background is painted by the shell (`bg-surface-primary`), where the reference states it
  on the drawn frame. Deliberate — see `src/shells/DEVIATIONS.md`.

**Content, for whoever builds the screen (T-110)**

- `.btn-primary` is `width:100%` and D9's Save changes is written `width:auto`. `cx` appends rather
  than overrides, so the story shrink-wraps the button in an `inline-flex` parent. A screen that
  wants an auto-width primary button has to do the same, or `<Button>` needs a width prop (T-012's
  deferred list already names this).
- `<TextField>`'s label and field spacing runs a couple of pixels tighter than `.field`'s, which
  accumulates down the form.
