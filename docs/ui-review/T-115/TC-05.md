## Deviations

<!-- One line per deviation the heat map shows: what differs, where, and whether it is intended.
     Everything below this comment survives the next run; everything above it is regenerated. -->

**Shell chrome (every screen here).** The reference draws these as full-screen mobile frames with their own
top bar and a pinned footer, and no tab bar. The built screens sit inside `AppShell` (the brief says to use
it), so each carries the shell's brand row with the Buy/Sell switch above it and the tab bar below it, and its
own back/title row is drawn in the content. That is the largest part of every heat map and is intended. Actions
are in the page flow (`ActionStack`) rather than `.btn-sticky`, because a pinned footer would sit on the tab bar.

**Shot against a stub.** The harness shot ran against the real app with a canned stand-in for the backend
(trade ids mapped to states) because no backend runs in the review environment; copy and layout are the real
screens, the data is illustrative.

- **No "Reason / Note" and no "Revised terms summary".** The counter endpoint takes no note, and the drawn summary repeats the diff above it. "What's changing" is built live from what the person edits.
- **Only price and address can be changed here.** The drawn Delivery row ("Courier / Buyer pickup") is not a term the platform stores, and item details are not editable in a counter on this screen.
- **The inputs come first and "What's changing" follows**, because the reference draws the diff over a form that is not shown. Each change is a `CounterDiffRow`: the old value struck through, the new in emerald.
- **"Send counter-proposal" is disabled until something differs**, with a line saying so. The counter carries the trade's revision, so a counter against a trade that moved on is refused rather than landing.
