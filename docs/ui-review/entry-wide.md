# Entry screens with no wide drawing (F-067, F-072)

The reference draws DX-01 and TX-01 only. Every other entry screen is drawn on a phone, so these have no frame to
score against; each was captured at 1280 and 820 through the stand-in (`pnpm visual-capture`) and read by eye, and
every entry route was loaded in `next start` at 1280, 820 and 390 with no console or hydration error (the only
errors are the stand-in's 404s for the terms and states reads, which also occur at 390).

Frame, by owner decision: **desktop = DX-01's two columns** (brand story and Trade Code entry on the left, the
screen's phone content and actions on the right, actions stacked under the form, no sticky footer); **tablet =
TX-01's centred card** (wordmark above, actions under the form side by side, a Back link in the card in place of the
top bar); **phone unchanged**.

Deviations and decisions for the owner:

- **Trade Code entry is on log in, welcome and sign up** (the desktop box and the tablet line), not on the screens a person is in the middle of (Terms owed, first password, session ended, code entry, reset). A logged-out visitor cannot see a trade from a code (the platform lookup needs a session), so the box says they log in first. See DX-01.md.
- **Keep me signed in** is not built; see DX-01.md.
- On tablet the buttons of every screen sit side by side at their own width (TX-01's pattern); long labels wrap onto a second row rather than shrink.
- Not checked in a browser: TOS2 and set-password with real data (the stand-in has no terms or session read for them); both are covered by the jsdom suites at all three widths.
- **A phone in landscape at 768px or wider gets the tablet card**, the same breakpoint as the rest of the app. Accepted.
- **First paint.** The server HTML carries every width's variant and CSS chooses (`hidden lg:flex`, `md:hidden`, ...), so a desktop or tablet window is right before any script runs (checked with JavaScript off at 1280 and 820). `useSeen` answers "unknown" during the server render and hydration, then only the variant for the window stays in the DOM: every route has exactly one visible `h1` at 390, 820 and 1280, and no brand panel is in the DOM below 1024. One known residue: on log in at desktop the phone label ("Phone number") and its helper line show until hydration, then read "Phone number or email".
- **Phone against staging, pixel for pixel.** `origin/staging` was built in a scratch copy and both builds were captured at 390x844 (viewport and full page) for welcome, log in, sign up, terms, verify, the full Terms, reset, new password, session expired, status, update required and too many attempts (a 429 on log in): **0 differing pixels on all 24 captures.** With the window cut to 500px and a 1600px body added, the top bar stays at the top and the footer at the bottom edge on both builds, and a short body pins its footer to the bottom of the window on both. CameraPermission does not use `EntryFrame`, so it is not part of this.
