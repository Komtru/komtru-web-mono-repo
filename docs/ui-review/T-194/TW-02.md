## Deviations

**Shell chrome and the stand-in.** The reference draws a full-screen mobile frame with its own top bar and pinned footer; the built screen sits in `AppShell` (brand row, mode switch, tab bar), `ScreenHeader` stands in for the drawn bar and the actions (`ActionStack`) sit in the page flow above the real tab bar, so the built shot is taller and every row below the header is offset. The shot walks the real screen in Chromium against `next dev`, with the platform's routes answered from canned data (TechEdge NG, iPhone 13 · 128GB), so names and amounts are illustrative. Amounts print with kobo (`₦195,000.00`) as the rest of the app does; the reference prints whole naira. The reference's `₦198,500` total is ₦195,000 + the ₦3,500 Buyer Protection Fee here, not ₦3,500 delivery.

**Real differences (intended, and why)**

- **Read-only, not inputs.** The reference draws pills and a destination field that rebuild the agreement summary. A trade whose terms were accepted has nothing to rebuild: no route edits an accepted version (a change before acceptance is a counter, F-017). Category, inspection period, delivery method, destination and courier charge are therefore rows, only the ones the platform has, and the footer's "Update terms summary" becomes "Back to the trade" under the reference's locked-terms sentence.
- **The "48 hours — Electronics standard" banner is read from the standard the trade pinned**, so it shows the trade's own category and minimum, and is simply absent if that read fails. The courier-quote caveat is not drawn: the charge shown is the seller's commitment on the accepted version, not a live estimate.
