Shot for **T-013** (`ui-kit` layout shells) against Storybook story `Shells/PublicShell` →
`SellerProfile`. The shell — no navigation, 24px page padding, the 280px rail beside a flexible main
— is this ticket's; the passport hero and the listing rows are stand-in content. T-114 owns both.

**Shell chrome (T-013)**

- Nothing. The two columns, the 24px gap and the rail width land on the reference. D8 states that
  split inline rather than in a rule, so it is asserted in `PublicShell.test.tsx` and at all four
  widths in `four-widths.test.tsx` rather than by parity.

**Content, for whoever builds the screen (T-114)**

- The avatar keeps `<Avatar>`'s indigo-soft/indigo pair; `.passport-hero .avatar` refills it with
  `rgba(255,255,255,.15)` on white. `cx` appends, so a class cannot take the tone off — the hero is
  T-114's component and the tone belongs on it.
- `.passport-hero`'s gradient ends on `#1A2440`, a literal with no `:root` token. The story writes
  it with an eslint exemption; the real component should decide whether to tokenise it.
