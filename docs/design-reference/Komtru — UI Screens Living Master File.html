Gap audit — recommended next screens

What I would add next, beyond the registration flow

These are the missing product states I found by following the Park Agent lifecycle end-to-end, not by changing the existing visual language.

1. Agent invitation / claim

A hub should be an entity, while a person is an authorized operator. Support “You’ve been invited to operate Jibowu Hub” and prevent two people from silently creating duplicate hubs for the same terminal.

2. Changes requested loop

PH6 currently jumps from submitted to a binary TrustOps decision. Add a first-class “Changes requested” state so reviewers can ask for one precise document without forcing a full restart.

3. Hub vs. agent separation

Store Hub ID, Park/Operator, Branch, Primary Agent and Staff separately. This makes staff replacement possible without corrupting the custody history.

4. Permission model

Receive, inspect, release, add staff and manage payouts should not all be the same permission. Release rights should remain tied to verified identity and the PIN guard.

5. Operating-state controls

Add open/closed hours, temporary closure, handover blackout and “unable to receive” states. Buyers need to know when a hub is genuinely available, not merely verified.

6. Custody exception queue

Damaged parcel exists already, but lost/late arrival, wrong parcel, wrong recipient, repeated PIN mismatch, no-show pickup and unauthorized staff access need explicit paths into TrustOps.

7. Re-verification & suspension

Authorization can expire or the primary agent can change. A TrustOps lifecycle screen should pause only the affected custody permissions while preserving existing Trades and evidence.

8. TrustOps SLA + auditability

Every case needs owner, SLA clock, reason for reassignment, evidence request history and final decision. The existing Design System already establishes that decisions should be auditable and AI should suggest rather than decide.

UI/UX refinement I recommend across the whole Park Agent surface

Persistent hub identityKeep “Jibowu Park Hub” + Hub ID visible in the top shell.
One custody statusUse Active / Held / Suspended rather than many ambiguous labels.
Action-first dashboardPut Arriving, Awaiting Pickup and Exceptions ahead of earnings.
Evidence by defaultCamera capture should timestamp and attach hub identity automatically.
Reason before riskSuspensions, freezes and reassignments always show why and what remains usable.
Role switch clarityShow Buyer / Merchant / Park Agent as distinct modes with their own trust state.
