# T-040 — Files and evidence (M20) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `src/modules/files` — one upload/retrieval pipeline for every module's file needs, backed by five pooled Cloudinary accounts, with a per-file visibility class checked on every read, an access log for the sensitive categories, and tombstoning that keeps a soft reference resolvable.

**Architecture:** The browser uploads straight to Cloudinary with a signature this API computes locally, so the backend never proxies bytes. Signing is pure arithmetic and lives in `infrastructure/providers/cloudinary.signing.ts`, which a request handler may call. Everything that actually dials Cloudinary — finalize reconciliation, tombstone destroy, usage sync — lives in `infrastructure/providers/cloudinary.client.ts`, which only `files/jobs/` may import (design §4.4, T-028). The access decision is one pure function over a file's class, the caller, and the caller's grants.

**Tech Stack:** TypeScript strict ESM (`.js` on relative imports), drizzle-orm + drizzle-kit, zod 4, BullMQ through `platform/queue`, the transactional outbox through `platform/events`, Vitest.

**Spec:** `docs/specs/module-20-file-and-evidence-management.md` (cited as "M20 §n" / "D n"), plus `docs/superpowers/specs/2026-10-05-komtru-platform-design.md` §4.2, §4.3, §4.4, §7.2 (cited as "design §n"). Ticket: `docs/tickets/04-files-notify-config.md` § T-040.

## Global Constraints

- Exact dependency versions, never `^`. No new runtime dependency is needed: the Cloudinary wire protocol here is a SHA-1 and three HTTP calls, and the official SDK's `cloudinary.config()` is process-wide, which a five-account design would have to fight.
- TypeScript strict, ESM, `.js` extension on every relative import. zod 4 (`z.uuid()`, `z.iso.datetime()`, not `z.string().uuid()`).
- Nothing lives in `public`: every table is in the `files` pgSchema. Cross-schema references are plain `uuid` columns with no foreign key (design §4.2).
- Every route is declared with `defineRoute` and carries `scope`, a `summary`, an explicit `retryable` on every mutating method, and `paginated` on any collection. `mountRoutes` enforces `scope` and `permission`.
- The caller's identity comes from `actor.principal` via `requireUserId(actor, detail)`. Never parse `actor.key`.
- Permissions come from the existing M1 §12.2 catalogue (`PERMISSION_CODES`). This ticket adds no `file.*` permission: a new code needs a row in the twelve-role matrix, which is identity's file and a guaranteed merge conflict.
- `files/infrastructure/providers/cloudinary.client.ts` is the only file in the module that may call `fetch`, and only `files/jobs/**`, `files/index.ts` and `files/module.ts` may import anything under `files/jobs/`. Both `komtru/provider-clients` (ESLint) and `test/platform/provider-boundaries.test.ts` (source scan) enforce this.
- Migration numbers `0027_` and `0028_` are this ticket's. Generate on top of the current `main`, then `pnpm migration:safety --update-lock --update-invariants`.
- Cannibalized files carry a `// Cannibalized from kumtru/backend-apis/src/modules/files/<path> (T-001)` header and say what was adapted. Old tests are never copied.
- Comments are sparse and explain _why_.
- Repo lint rules this plan must not break: `komtru/module-boundaries` (another module is reachable only as `'../<name>/index.js'`); `komtru/pgbouncer-safe` (no `LISTEN`, `PREPARE`, `pg_advisory_lock` — the rotation cursor uses `SELECT … FOR UPDATE`, which is transaction-scoped and safe through PgBouncer); `no-console`; `consistent-type-imports` with inline `type`; `no-floating-promises`.
- Logging is `logger.info({ structuredFields }, 'files: lower-case message')`, errors as `{ err }`. Nothing here logs a storage object id alongside a user id, and nothing ever logs a credential.
- zod 4 idioms: `z.strictObject({...})` rather than `.strict()`; `z.uuid()`, `z.iso.datetime()`.
- drizzle 0.45: table extra-config is the **array** form `(table) => [index(...), check(...), uniqueIndex(...)]`. A partial unique index is `uniqueIndex(name).on(col).where(sql\`…\`)`.
- The `files` enums are declared inline in `enums.ts` with per-value comments (identity's variant), not added to `@komtru/shared-types`: nothing in this ticket puts a file category on the wire as a shared contract, and a shared-types change is a guaranteed conflict with every branch in flight.
- Secretlint runs on every staged file: tests use obvious placeholders (`'abcd'`, `'demo'`), never a value shaped like a real Cloudinary secret.
- **Do not run infra tests.** Never set `KOMTRU_INFRA_TESTS=1`; never run `pnpm infra:up`/`infra:down`. Write `*.int.test.ts` files, do not execute them. Do not run `pnpm tickets:index`. Do not merge or push.
- Turbo's cache is shared across worktrees: verify with `--force`.

## Review Focus

1. **A client that finalizes a ticket it never used.** `POST /files/:id/finalize` must not take the client's word; the job asks Cloudinary, and a file with no asset never becomes servable. A dispute whose "evidence" was never uploaded is worse than a missing photo. — Task 8.
2. **A file id used as an existence oracle.** "No such file" and "not yours" must be the same 404, or `GET /files/:id` tells an attacker which dispute-evidence ids exist. The one exception is `TOMBSTONED` (410), which says nothing an authorised caller did not already know. — Task 9.
3. **Two uploads racing for the same rotation slot.** Without `FOR UPDATE` on the cursor row both requests read the same `last_account_id` and pick the same account, so the pool degenerates under exactly the concurrency rotation exists for. — Task 7.
4. **An access-log write that fails.** It must not fail the read it was auditing, and it must not pass in silence. — Task 9.
5. **A client-supplied capture timestamp.** The body is a `z.strictObject` with no field for one, so a park agent app with a wrong device clock gets a 400 rather than a custody photo stamped in the future. — Task 10.

## Not built here, and why

**M20 §8 "events consumed"** — `compliance.retention_policy_applied` and `compliance.dsr_fulfilled` (M15, T-104) and `dispute.opened` (M3, T-080). None of those events exist yet; subscribing to an event nobody publishes is a handler that can only be wrong by the time it fires. What this ticket ships instead is the two functions those handlers will be three lines on top of — `tombstoneByUploader` and `grantAccess` — exported from the barrel, so T-104 and T-080 each add their own subscription next to the event they define. This goes on the ticket's **Deferred** line.

**Types used across tasks:** `Reader = Db | Tx` (a read that works inside a caller's transaction or outside one), declared once in `src/modules/files/infrastructure/postgres/reader.ts`, mirroring `ledger/infrastructure/postgres/accountsRepository.ts`'s `Reader`. `Tx` is `platform/events/publish.js`'s.

`enums.ts`, M20 §3.1 plus this ticket's two additions:

- the partial unique index `storage_accounts_singleton_pool` on `(pool) WHERE pool IN ('PROFILE','CHAT_ATTACHMENT') AND status <> 'DISABLED'`
- a partial unique index `storage_accounts_rotation_order_uidx` on `(pool, rotation_order) WHERE rotation_order IS NOT NULL` — the old backend's conflict translator names this constraint, and without it two accounts can claim slot 2 and rotation silently depends on row order
- a check `storage_accounts_credits_pct_range` on `credits_used_pct BETWEEN 0 AND 100`

`files.ts`: `file_records` as M20 §3.4, plus

- `upload_state fileUploadState NOT NULL DEFAULT 'PENDING'` and `finalized_at timestamptz`
- `size_bytes bigint NOT NULL DEFAULT 0` — unknown until the bytes land
- **capture metadata** (the ticket's sixth bullet): `capture_received_at timestamptz` and `capture_hub_id uuid` (plain uuid, soft ref to `park.park_hubs`). There is deliberately **no** column for a client-supplied capture time; `capture_received_at` is written from the database clock when the server is first told the bytes landed, which is the only timestamp this module can vouch for.
- a check `file_records_capture_hub_category` — `capture_hub_id IS NULL OR category IN ('CUSTODY_EVIDENCE','PROOF_OF_DELIVERY')`, so a hub id cannot be attached to a listing photo
- a check `file_records_tombstone_reason` — `status <> 'TOMBSTONED' OR tombstoned_reason IS NOT NULL`
- the unique index `file_records_account_object_unique` on `(storage_account_id, storage_object_id)` and the three indexes M20 §3.4 lists, plus `file_records_pending_idx` on `(created_at)` `WHERE upload_state IN ('PENDING','RECONCILING')` for the abandoned sweep

`file_access_grants` and `file_access_log` as M20 §3.5/§3.6, with `denied_reason text` added to the log (a log that records only successes cannot show a pattern of refused reads, which is the thing an investigation looks for) and a real same-schema FK on `file_id` with `onDelete: 'cascade'`.

`index.ts` re-exports all five files, and exports the inferred types.
