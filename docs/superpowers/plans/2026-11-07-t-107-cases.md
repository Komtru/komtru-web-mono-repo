# T-107 Universal case model, work queue and advisory — plan

Scope: `apps/backend-api/src/modules/cases/**`, migration `0040_cases_*`, one new identity barrel export (`liveRoleCodes`). Test first, commit per green step.

## Shape (M15 "index, not copy")

The `cases` schema holds an index of work items. The owning module (disputes, trust, park, risk, ...) keeps its own record and calls `registerCase` in its own transaction; the index stores a subject reference (`subject_type`, `subject_id`), never a copy of the subject.

Tables (schema `cases`):

- `cases`: id, `case_number` (identity, shown as `C-002841`), type (9 types), subject ref, title, owner, priority, state, SLA (`sla_hours`, `sla_started_at`, `sla_due_at`), `facts` (small non-PII jsonb the owning module keeps current, read by the advisory), timestamps. Unique on (type, subject_type, subject_id) so registering twice returns the same case.
- `case_evidence_requests`: what staff asked for, from whom, due when, open or resolved.
- `case_decisions` (append-only): outcome, reason, **policy citation** (NOT NULL), decider.
- `case_trail` (append-only): the case's trust trail; one row per change (registered, taken, reassigned with reason, priority, escalated, evidence requested or resolved, state change, decision, closed).

## Decision write (acceptance: trust trail + admin action log + policy citation)

One transaction: `case_decisions` row (carries the citation), `case_trail` row, `identity.identity_audit_log` row `ADMIN_CASE_DECIDED` with reason and citation (the admin action log until T-103's own table exists, the same stand-in geo uses), outbox event `cases.case.decided`. Every other staff mutation writes the trail and an audit row too.

## Advisory

`domain/advisory.ts`: `AdvisoryProvider` interface; v1 `ruleBasedAdvisory` is pure, one rule set per case type. Result: `{ label: 'AI-suggested — not a decision', suggestion, rationale[], source: 'RULES_V1' }`. The advisory service takes a read-only handle (`Pick<Db,'select'>`) and has no import of the decision writer. Tests: unit (a Db whose write methods throw), and integration (decision and trail row counts unchanged after calling it; `GET` only; the decision route rejects a body that carries advisory fields).

## HTTP (STAFF scope; `cases.view` reads, `cases.manage` writes)

- `GET /cases/queue?view=mine|unassigned|escalated|sla_at_risk` + filters; `GET /cases/queue/counts` (P0-01 tiles).
- `GET /cases` universal list (type, state, priority, owner, subject, q by case number); `GET /cases/:id` (P0-02 overview, evidence, decisions); `GET /cases/:id/trail` (paginated); `GET /cases/:id/advisory`.
- `POST /cases/:id/take | reassign | escalate | priority | evidence-requests | evidence-requests/:rid/resolve | decisions`.
- All lists cursor-paginated.

## Barrel for owning modules

`registerCase`, `syncCaseFacts`, `closeCaseForSubject`, `fulfilEvidenceRequest`, `caseTypes`, events, schema.

## Owner decisions pending (defaults applied)

1. SLA hours by type: DISPUTE 48, KYB 72, MERCHANT_APPLICATION 72, IDENTITY 24, FRAUD 24, CUSTODY 48, PAYMENT_EXCEPTION 24, TRADE_PROPOSAL 24, PARK_HUB_APPLICATION 120. Not documented anywhere; code constants, to be moved to config.
2. "SLA at risk" = breached, or within the last 25% of the policy window, on a case that is not decided or closed.
3. The SLA clock keeps running while a case awaits evidence (no pause).
4. A case is decided only by its owner (take it first); a decision moves it to DECIDED and the owning module closes it through `closeCaseForSubject` once the outcome is executed.
5. The policy citation is free text (1..200 chars): there is no policy registry until the Policies console (T-150s).
6. Reassignment target must hold a live role carrying `cases.manage`.
7. Reads are not written to the audit log (queue polling would drown it); every mutation is.
8. No manual "Create case" in P0-01: a case needs a real subject, so owning modules register.
9. Admin action log: `admin_action_log` (T-103) does not exist yet; identity's audit log stands in, to be switched when T-103 lands.
