# T-003 Local Infrastructure and Environment Wiring Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One command starts Postgres, PgBouncer, Redis and Mailpit locally; one command writes the backend `.env` from the old backend's live credentials without ever printing a value; and commits are blocked if they contain secrets.

**Architecture:** `docker-compose.yml` at the root with health-checked services. Node scripts under `scripts/env/` and `scripts/` (ESM, tested by the root `test:repo` Vitest suite). The credentials file lives only in the main checkout (git-ignored), so scripts resolve it through `git rev-parse --git-common-dir`.

**Tech Stack:** Docker Compose, postgres:16-alpine, edoburu/pgbouncer, redis:7-alpine, axllent/mailpit, secretlint 13, `pg` and `ioredis` for the infra smoke test.

**Spec:** `docs/tickets/00-foundations.md` (T-003); design §3.4 and §4.4.

## Global Constraints

- Never print, log or commit a value from `docs/specs/backend-apis.env`. Scripts print variable names only.
- Local database name `komtru_v2_dev`; never point the new build at `komtru_dev` (the old backend's database).
- PgBouncer in transaction pooling mode; `POSTGRES_URL` goes through PgBouncer, `POSTGRES_DIRECT_URL` goes straight to Postgres (migrations).
- Keep the old variable names so the old `.env` drops in unchanged (design §3.4).
- Every compose service has a health check.

## Review Focus

1. A teammate who runs the env script twice must not lose a hand-edited `.env`: refuse to overwrite without `--force` (Task 2 test).
2. The secrets source missing (fresh machine) must give a clear message naming the expected path, not a stack trace (Task 2 test).
3. A secret value pasted into a non-`.env` file (a test fixture, a doc) must be caught at commit time (Task 4 test).
4. The env script's own output must not leak values even on error paths (Task 2 test captures stdout and stderr).
5. Port clashes with an old local Postgres or Redis: ports are configurable through `KOMTRU_*_PORT` variables with non-default defaults (Task 1).

### Task 4: Commit-time secret scanning

**Interfaces:** `findSecretsInStaged({ cwd, secretValues }): Array<{ file: string, kind: 'KNOWN_VALUE' | 'PATTERN' }>` — scans added lines of staged files; `loadSecretValues(envPath): string[]` returns values of length ≥ 12 that are not booleans, numbers or plain localhost URLs.
