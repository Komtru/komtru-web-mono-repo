# T-048 Configuration (M17) plan

Scope: `apps/backend-api/src/modules/config/**`, one migration, tests. Fees stay in `config/fees.yaml` only.

1. Schema (`config` pg schema): `platform_settings (namespace, key)`, `feature_flags (code)`, append-only
   `config_change_log`. One generated migration plus one custom migration for the append-only trigger.
2. Domain: seed definitions (spec M17 section 4 plus the five T-048 additions), value typing and bounds,
   a fee-lookalike guard that rejects any key or flag code made of fee tokens, events
   `config.setting_changed` and `config.feature_flag_toggled`.
3. Services: typed accessor over Redis (read-through, per-key, short TTL), invalidated after commit and by a
   `config.setting_changed` subscriber; admin writes in one transaction (row, change log, identity audit row,
   outbox event); idempotent seed that never overwrites an operator's edit.
4. HTTP: `GET/PUT /admin/config/settings/:namespace[/:key]`, `GET/PUT /admin/config/flags[/:code]`,
   `GET /admin/config/change-log`, STAFF scope, `config.view` for reads and `config.manage` for writes (both
   already in the RBAC catalogue, so no catalogue change). A reason is required on every write (body,
   `?reason=` or `X-Admin-Reason`), 400 when missing.
5. Test first for each step: domain unit tests, route tests with stubbed services, infra tests for the
   database, cache invalidation, change log and audit.
6. Out of scope: the D2 content proxies (templates, risk rules, ticket queues). Their owning modules (M11,
   M13, M10) do not exist yet; they are listed as an open question.

## Decisions and notes (after review)

- **Event names:** the platform requires three-segment event types, so M17 section 5's `config.setting_changed`
  is `config.setting.changed` and `config.feature_flag_toggled` is `config.feature_flag.toggled`.
- **No-op changes write nothing (deliberate):** setting a value, or a flag, to what it already is writes no
  change-log row, no audit row and no event, and returns 200 with the stored view. A reason is still required.
- **Cache:** request path invalidation is best-effort; the event subscribers throw on a Redis failure so the
  outbox redelivers. The 60s TTL bounds the one read-after-write race and is accepted.
- **Fee guard:** long unambiguous words (`fee`, `commission`, `bps`, `kobo`, ...) are also matched in the
  separator-stripped string; short ones (`cut`, `rate`, `margin`, ...) only as whole tokens; `take_rate` and
  `payout_share` as phrases. A future `rate_limit_*` key is refused by design.
- **Settings values:** DECIMAL supports `min`, `max` and `maxScale`; STRING is trimmed and may not be empty.
- **Flag creation race:** the insert is `ON CONFLICT DO NOTHING`; the loser falls through to the update path.

### Owner decisions pending

- `trades.payment_deadline_hours = 24` and `trades.delivery_deadline_days = 7` are placeholders; no spec states them.
- `config.manage` is SUPER_ADMIN only (already in the catalogue); OPERATIONS_ADMIN reads only.
- Reads write no audit rows. No feature flags are seeded.
- The section 6 content proxies (templates, risk rules, ticket queues) land with their owning modules.
