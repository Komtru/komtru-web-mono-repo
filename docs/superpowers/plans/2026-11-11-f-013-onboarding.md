# F-013 — First-time onboarding walkthrough (T-112)

Screens OB1–OB5 (v2). Frontend only: the notification opt-in already exists (F-007, T-045): `POST /me/devices`
stores a device and its push token, and the FCM adapter reads `devices.push_token`. No backend code, no migration.

## Decisions

- **Routes** (the reference's own URLs, behind the session): `/welcome/1`, `/welcome/2`, `/welcome/3`,
  `/welcome/notifications`, `/welcome/done`; `/welcome` goes to `/welcome/1`.
- **Entry:** only a **new sign-up** is sent there. The E3 verify screen passes `next=/welcome` through `afterSession`, so
  terms-updated and set-password still come first and then hand on to the walkthrough. Log-in never shows it.
- **Skippable, once, remembered:** Skip (OB1–OB3) leaves the walkthrough for Home and records it as done on the device.
  Finishing (OB5) records the same. Once done, `/welcome/*` redirects to `/`. A new sign-up on the device clears the mark.
  Skip does not ask for notifications; the ask is repeatable later in notification preferences (F-046).
- **OB4:** "Allow notifications" calls `Notification.requestPermission()`; granted, it asks a `PushTokenSource` for a
  token and registers the device with `POST /me/devices`. "Not now", denial and an unsupported browser all continue to
  OB5, never blocking. A browser that already denied gets the explanation instead of a button that does nothing.
- **api-client:** `registerDevice` endpoint + `useRegisterDevice` hook, tested.
- **OB5:** "Start a Trade" -> `/trade/new`. "Enter a Trade Code" reveals a code field that opens `/trades/<code>`
  (there is no code-entry screen in v2). Name in the heading is the first name typed at sign-up, when still known.

## Owner questions

1. **Web push tokens.** The backend sends through FCM v1, so a browser needs a Firebase **web** registration token
   (Firebase web config + VAPID key + the Firebase SDK and a `firebase-messaging-sw.js`). None exists in the repo and
   no raw Web Push subscription can be stored (it would be reported as an invalid token). OB4 therefore asks the
   permission and registers the device only when a token source is configured; none is yet. Provide the Firebase web
   project, or decide on VAPID/Web Push in the backend.
2. Should returning users on a new device see the walkthrough? Default chosen: no, sign-up only.
3. Does Skip on OB1–OB3 skip the notification ask too? Default chosen: yes (the reference says skip at any point).
4. Should "Replay the tour" live in Account? Not drawn; not built (`/welcome` is not reachable once done).
5. "You're all set, Amaka" needs the first name; there is no profile read yet, so it is the name typed at sign-up or none.
