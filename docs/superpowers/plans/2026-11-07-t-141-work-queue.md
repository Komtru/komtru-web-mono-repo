# T-141 Work queue and universal case — plan

Scope: `apps/operations-app` screens P1, OP-01, OP-02, OP-03, OP-04, OP-12, OP-19 and the universal case layout (AC10), against the T-107 cases API. One new api-client module (`packages/api-client/src/cases.ts`) for the endpoint contracts. No database migration and no backend change.

## Routes (all under the Work Queue section, `current="queue"`)

| Route                 | Screen | Reads                                                                           |
| --------------------- | ------ | ------------------------------------------------------------------------------- |
| `/queue`              | OP-01  | `GET /cases/queue/counts`, `GET /cases/queue?view=mine` and `view=escalated`    |
| `/queue/mine`         | OP-02  | `GET /cases/queue?view=mine` with type chips                                    |
| `/queue/team`         | OP-03  | `GET /cases/queue?view=unassigned`; `POST /cases/:id/take`                      |
| `/queue/alerts`       | OP-04  | `view=escalated` and `view=sla_at_risk`                                         |
| `/queue/cases`        | OP-19  | `GET /cases` with type, state, priority chips and a case-number search          |
| `/queue/cases/[id]`   | AC10   | detail, trail, advisory; take, reassign, escalate, priority, evidence, decision |
| `/queue/check-in`     | P1     | `GET /cases?type=TRADE_PROPOSAL` (open, then decided)                           |
| `/trades/[reference]` | OP-12  | `GET /cases?subjectType=TRADE&subjectId=` and each case's trail                 |

A tab strip (Today, My work, Team queue, Alerts, Cases) sits under the page head. The reference sidebar (Today, My work, Trades...) was replaced by T-140's twelve sections; the five orient screens become tabs inside Work Queue.

## Steps (test first, commit per green step)

1. api-client `cases.ts`: endpoints and schemas mirroring `modules/cases/http/validations.ts` (dates as ISO strings).
2. `src/cases/format.ts`: case type to area, clock text ("1h 40m", "Overdue"), state and priority labels, tone.
3. `src/cases/hooks.ts`: query keys, queue/list/detail/trail/advisory queries, mutation helpers that invalidate the queue.
4. Shared pieces: `CaseTabs`, `CaseTable` (DataTable rows with the clock).
5. OP-01, OP-02, OP-03, OP-04, OP-19 pages.
6. Universal case page: `CaseLayout` (case facts, evidence requests, Trust Trail) beside a `DecisionPanel` (advisory from the API, outcome, reason, policy citation).
7. OP-12 trade view and P1 mobile check-in.
8. Visual check notes in `docs/ui-review/T-141/`, ticket status, full verification.

## Safety rules carried through

- The advisory comes from `GET /cases/:id/advisory`, renders in `AdvisoryBox` through `DecisionPanel`'s `advisory` prop (prose only), and never fills a form field or enables a button. The decision request body is built from the form only.
- Mutating buttons show only with `cases.manage`; the backend remains the boundary.
- A decision needs an outcome, a reason and a policy citation; the button stays disabled until all three are present.

## Known backend gaps (not built here)

1. No staff roster or capacity endpoint: OP-03 "Who has capacity" and the reassign target picker cannot list people. Reassign takes a user id typed in.
2. No "recently decided" feed or per-area/oldest-clock aggregate: OP-01 "Decided today", "Where the work is" (beyond what counts give) and "Just decided" are not drawn.
3. No staff Trade read model: OP-12 draws the cases and Trust Trail attached to the trade, not the stage rail, parties or money.
4. No alert/notification inbox or escalation-rule store: OP-04 derives alerts from escalated and SLA-at-risk cases and states the rules the queue actually applies.
5. Staff names: cases carry user ids only, so owners show as "You" / "Unassigned" / short id.
6. `GET /admin/me` was already a T-140 follow-up; the whole console stays empty without it.
7. No owning module calls `registerCase` yet, so the queue is empty against a real backend until they do.

## Owner decisions pending (defaults applied)

1. Route layout: orient screens are tabs under `/queue`, not top-level `/today`, `/work`, `/alerts` as the reference URLs show.
2. Area names for case types: DISPUTE = Cases, FRAUD = Risk, KYB/IDENTITY/PARK_HUB_APPLICATION/MERCHANT_APPLICATION = People, TRADE_PROPOSAL = Proposals, PAYMENT_EXCEPTION = Money, CUSTODY = Custody.
3. P1 "flagged" = open TRADE_PROPOSAL cases; "cleared today" = decided or closed TRADE_PROPOSAL cases updated since local midnight.
4. Trade 360 looks cases up by `subjectType = 'TRADE'` and the trade reference as `subjectId`; owning modules must register trade cases with that subject type.
5. Reassign is a typed user id until a staff directory exists.
6. Opening a case from a table row is a normal link, no side panel.
7. The queue refreshes by refetching on window focus and every 60 s; realtime waits for the socket events of the cases module.
