### API gaps (reported, not patched)

1. **No `GET /trades` list.** Q1 "My Trades" and the buyer tab need one. Stopgap: a device-local index of trade ids (`src/trade/known-trades.ts`), each read through `GET /trades/:id`. Replace with the list route when F-022 adds it.
2. **`TradeView` carries no counterparty identity** (no name, avatar, trust figures). Screens that draw a seller strip show the name/stats only where we looked the person up ourselves (the proposer typed them). The receiving party sees "the buyer / the seller" until the view gains a `counterparty` card.
3. **No listings API** (T-056 / F-080). I3 "from listing" cannot show a listing, its price or its reviews. `/trade/new` is the I3 layout with a typed item instead of a listing card; the reviews block and "Message to seller" are not drawn (no endpoint stores a message, no reviews endpoint).
4. **`POST /trades/:id/send` returns no claim token or link** and the platform never delivers an invitation. A non-user is invited by phone/email and claims on verification; the inviter shares the Trade Code themselves. (`POST /parties/invite` returns a token but `send` does not call it through HTTP.)
5. **Trade Standards expose only** window, item fields, proof media, IMEI flag, deadline days. CTS1 also draws "Clock starts", "Buyer can request up to", "Full refund if", "Cancellation". Those are policy copy with no API source; they are **not drawn** (conservative default, see questions).
6. **ID upload on G3** has no endpoint outside KYC. G3 renders the held state only (F-021 is post-MVP).

### Backend changes on this branch (from the second review)

- `standardVersionId` on every trade view: the id of the exact standard version the trade froze. The seller's
  proof requirement is read from `GET /config/trade-standards/versions/:id` with that id, so it stays right after a
  newer version is published; a failure to read it is an error, never a lower bar. No migration.
- `counterparty` on the proposal routes' trade view (`GET /trades/:id`, create, send, counter, accept, decline,
  cancel, claim), with the same display and privacy rules as the list. The party strips read it from the trade.
- The client mirrors the platform's proof rule (`checkProofMedia`): `minPhotos` cannot lower the bar below one piece
  of media, and photos and a required video are counted apart.
