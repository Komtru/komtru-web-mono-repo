# T-014 `ui-kit` TrustOps Patterns Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `@komtru/ui-kit` exports the composite patterns every TrustOps console screen is assembled from — `DecisionPanel` (with `AdvisoryBox`, the human-decides divider and `PolicyCite`), `CaseLayout`, `EvidenceMatrix`, `Timeline`/`TrustTrail`, `KpiCard`, `DataTable` with a `FilterBar`, and `PeriodFilter` — each matching the reference HTML's declarations, each with a Storybook story per documented state, and each with a Vitest + Testing Library test that includes an `axe-core` accessibility pass.

**Architecture:** A TrustOps pattern is a composition of T-012 primitives plus the reference's own case-review rules (`.case-header`, `.case-layout`, `.ai-recommend`, `.human-decides`, `.policy-cite`, `.p13-req`, `.p13-state`, `.p0-timeline`, `.dash-stat`, `.filter-bar`, `table.data-table`). Fidelity is proven the same way T-012 proved it: `test/trustops-parity.test.tsx` renders each pattern with `react-dom/server`, compiles its `class` attributes through the real `@komtru/config` Tailwind preset with the helpers already in `test/reference-css.ts`, and diffs the declarations against the rule the reference declares — with a `DEVIATIONS`/`ADDITIONS` table that fails on a stale entry. Behaviour, semantics and accessibility are tested separately per component under jsdom, and every component test ends with an `axe.run()` that must report zero violations.

**Tech Stack:** Node 22, TypeScript 6 strict (`moduleResolution: bundler`, `jsx: react-jsx`), React 19, Tailwind CSS v4.3.3, Vitest 5 + jsdom + @testing-library/react, **axe-core 4.14.0** (new, pinned exactly), Storybook 10.6.1, ESLint 9 flat config.

**Spec:** `docs/tickets/01-shared-packages.md` (T-014); source of truth `docs/design-reference/Komtru — UI Screens Living Master File.html`; screen map `docs/design-reference/SCREEN_INDEX.md`; the separation rationale is `docs/superpowers/specs/2026-10-05-komtru-platform-design.md` C14 and Q9 ("AI advisory: rule-based v1, behind an interface").

## Design plan

The brief pins the visual direction completely: the reference HTML is the design, down to `11.5px` and `1.5px`. The design work left for this ticket is therefore **not** palette or type — those are read, not chosen — it is where the markup has to be _more_ than the reference, and that budget is spent in exactly one place: the semantics of the decision surface.

- **Colour** — read from the reference's rules only. `.ai-recommend` is `--trust-indigo-soft` behind a **dashed** `--trust-indigo` border (the only dashed border in the whole document — the reference already says "this is provisional" in the border style). `.p13-state` maps `ready → --success-*`, `hold → --warning-*`, `review → --info-*`; that is the Pass/Gap/Check triple. `.p0-event`'s dot is `--trust-indigo` for every event; no tone variants are invented.
- **Type** — `--font-display` for panel headings (14–17px/600), `--font-body` for prose, `--font-mono` for anything a reader might have to quote back: case ids (`.case-id`), KPI values (`.dash-stat .dval`), table codes and amounts (`td.mono`, `td.amt`) and — notably — `.policy-cite`. The policy citation is set in mono _because it is a citation_, not decoration; it is the one typographic choice carried deliberately into the component API.
- **Layout** — `.case-layout` is `1.3fr 1fr`, evidence left, decision right. `.p0-timeline` is a 1px rail with 7px nodes. `.filter-bar` is a wrapping row, search first, chips after. All read from the reference.
- **Principle** — _advice is a region you read; a decision is a control you operate, and they are never the same element._

### Where the design is deliberately more than the reference

The reference draws the advisory, the divider and the buttons as three sibling `<div>`s. Visually that is the separation. Semantically it is nothing: to a screen reader it is one undifferentiated run of text ending in three buttons, and "AI-suggested — not a decision" is an unlabelled 10px line that a user skipping by control or by landmark never hears at all. The ticket calls this a trust-safety requirement, so the component has to carry the separation in the accessibility tree too:

```
┌─ section  region "Decision"  (DecisionPanel) ──────────────┐
│  h2  Decision                                              │
│  ┌─ section  region "AI-suggested — not a decision" ─────┐ │
│  │  (dashed indigo, advisory prose — STRINGS ONLY)      │ │
│  └───────────────────────────────────────────────────────┘ │
│  ──────── a human decides, always ────────   <p id=divider> │
│  ┌─ div  role=group  "Decision actions" ─────────────────┐ │
│  │  aria-describedby = divider + policy                  │ │
│  │  [ Require verification ] [ Forward ] [ Block ]       │ │
│  └───────────────────────────────────────────────────────┘ │
│  Applied per New-Buyer Proposal Policy §2.1   <p id=policy> │
└────────────────────────────────────────────────────────────┘
```

Three decisions make that structure load-bearing rather than cosmetic:

1. **The advisory is a named `region` landmark.** A user can jump to it, and — more important — jump _out_ of it. `role="region"` rather than `complementary`: a complementary landmark nested inside another landmark trips axe's `landmark-complementary-is-top-level`, and the advisory is never top level — it lives inside a case.
2. **`AdvisoryBox` accepts `string | string[]`, not `ReactNode`.** "Never inside the button group" is enforced by the type system and a runtime guard rather than by reviewer vigilance: a string cannot contain a button, so there is no way to render an action inside the advisory, and `tsc` rejects the attempt. This is the single most important API decision in the ticket.
3. **The action group is `aria-describedby` the divider and the policy cite.** Landing on the first action announces "Require verification before forwarding, button, a human decides, always. Applied per New-Buyer Proposal Policy §2.1" — the divider and the citation stop being decoration a screen reader skips, and become part of the control's description. `PolicyCite` is required on `DecisionPanel`, and an empty `actions` throws.

### Reviewed against the generic default

Running this brief without the reference would produce the SaaS-card kit: identical rounded cards, one radius, a soft grey shadow under each, an ALL-CAPS eyebrow over every heading, meta strings joined with middle dots. Three of those are in the reference _already_ and stay, because the brief's own words win: the `.ai-label` really is a 10px tracked uppercase line, and `.case-id` really does join its meta with middle dots. What was cut: no hover transition on `.p13-req` or table rows beyond the `tr:hover` the reference declares, no tone variants on the timeline dot the reference draws in one colour, no sort affordance on `DataTable` (not in the acceptance criteria), and no `KpiCard` sparkline. One radius is **not** used everywhere — the reference distinguishes `--r-lg` panels from `--r-md` inner boxes from the 8px `.rq-icon`, and that hierarchy is reproduced.

## Global Constraints

- **Stay inside `packages/ui-kit/src/trustops/**` and `packages/ui-kit/test/trustops/**`.** T-013 is working in `src/shells/**` in parallel. The only shared file is `src/index.ts`, which gets **one appended line** (`export * from './trustops/index.js';`, after `./tokens.js` — alphabetical and furthest from where T-013 will insert).
- The HTML is authoritative and literal. Every padding, radius, font-size and state colour is read out of it.
- Tailwind's default colour palette is retired; colours are token utilities only. Radii are `rounded-sm|md|lg|full`. `komtru-design/no-raw-hex` is on.
- ESM, `.js` extensions on relative imports, TypeScript strict, exact dependency versions (no `^`).
- Component tests start with `// @vitest-environment jsdom`; the parity test runs in node with `react-dom/server`.
- **Every component test file runs `expectNoAxeViolations`** on at least the component's default and its most complex state. `color-contrast` is the one rule disabled, because jsdom paints nothing and every element reports a zero-size box; that exclusion is stated in the helper with the reason.
- No `document`/`window` globals in `src/**` (ESLint runs with `react: false`): refs and React events only.
- Sparse comments explaining _why_, never _what_.

## Review Focus

1. **The advisory/action separation must hold semantically, and the axe test must prove it.** Not "the advisory has a class": the advisory must be a named landmark, must not be inside the action group's subtree, must contain no focusable element, and the action group must be described by the divider. A reviewer should be able to break the separation (move the advisory into the group) and watch a test fail (Task 3).
2. **`PolicyCite` is required and must carry a section.** "Applied per … §x.y" — a decision panel without a cited policy is a decision with no rule behind it. `policy` is a required prop; `section` is a required field.
3. **`PeriodFilter` must not let "lifetime" become a period.** The reference is explicit (line 8291: "Selected period controls period metrics. Lifetime intake remains all-time."). Lifetime is rendered outside the radiogroup with its own label, and a test asserts the radiogroup has exactly five options, none of them lifetime.
4. **`EvidenceMatrix` states must map to the reference's three, not to a colour.** `pass → .p13-state.ready`, `gap → .p13-state.hold`, `check → .p13-state.review`.
5. **Parity, not vibes.** Every pattern that has a reference rule is in `trustops-parity.test.tsx` with `DEVIATIONS`/`ADDITIONS` entries that fail when stale.
6. **Server components by default.** Only `PeriodFilter`, `FilterBar` and `DataTable`'s row-click surface need `'use client'`; `DecisionPanel`, `AdvisoryBox`, `PolicyCite`, `CaseLayout`, `EvidenceMatrix`, `Timeline`, `TrustTrail` and `KpiCard` must render in an RSC context with no hook and no directive. `useId` forces a boundary (T-012's `TextField` lesson), so ids are derived from a required `id`-free scheme: the panel takes an optional `idPrefix` and falls back to a module-level counter-free deterministic string built from the heading.
